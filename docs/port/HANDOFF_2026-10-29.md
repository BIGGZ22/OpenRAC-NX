## Vulkan work done (all built and tested on hardware)
1. **env.txt loader**: `sdmc:/switch/openrac/env.txt` (KEY=VALUE lines) is loaded into the
   environment at startup; what was applied goes to `env-applied.log`. Lives in
   `port/common/env.cpp` (`load_switch_file`, called from `read_environment` and `main`), so
   static constructors cannot read the environment before it loads.
2. **vulkan-startup.log** now also lists memory heaps/types, bindless state, timestamps and present
   modes (`vkgl::device_report`).
3. **Lazy frame-slot reclaim** (backport of upstream 9906aa6e): `advance()` no longer waits for the
   GPU at the end of present; `prepare_frame()` waits at the next frame's first GL use.
4. **Bindless materials off by default on Switch** (`OPENRAC_SWITCH_BINDLESS=1` re-enables), plus
   upstream's storage-buffer instance fix in `vkgl_draw.cpp`.
5. **Right-edge black flicker fixed**: `present-single-copy` is off by default on Switch
   (`renderer/render_opt.cpp`, `kPresentSingleCopyDefault`). Its clear-then-blit into the
   swapchain image showed through on NVK. Confirmed on hardware.
6. **Counters**: `OPENRAC_VK_COUNTERS=N` logs per-frame Vulkan command counts every N frames
   (`vkgl_present.cpp`, `log_counter_averages`).
7. **Shader dump**: `OPENRAC_DUMP_SHADERS=FOLDER` writes each linked program's sources and
   compiled SPIR-V+reflection (`<key>.vert/.frag/.comp/.prog`) (`shader_compiler.cpp`).
Patches 01-03 are also kept as files in `port/patches/switch-vulkan/`.

## What the Vulkan measurements showed (Novalis, 854x480, FRAME_COST + VK_COUNTERS)
- GPU-bound: GPU 12-22 ms/frame, CPU submit 5-9 ms, game sim <1 ms.
- GPU time tracks the number of draws (~10 us per draw on top of ~5 ms fixed), not triangles:
  halving triangles (CPU culling, `OPENRAC_GPU_DRIVEN_OFF=1`) or turning off sun shadows barely
  changed GPU time. Pipeline compiles 0 during play; barriers ~20/frame; uploads small.
- Conclusion: NVK's per-draw overhead on Maxwell is the bottleneck. GPU-driven culling also draws
  ~2.5x more triangles than CPU culling on this scene.
- Input works. A gray Pyrocitor in the vendor's side window (render-to-texture item preview) is
  still open; render thread on/off did not change it (unconfirmed by user).
- `perf-report.txt` (OPENRAC_PERF_CAPTURE) does not exist on Switch: debug tools are stubbed.
- The Vulkan SPIR-V cache is never saved on exit (28 shader compiles every launch) — open issue.

## deko3d game renderer ("dkgl") — builds and runs on hardware (2026-10-29 01:15)
Design: like vkgl, carry out the ~96 GL calls the renderers use (`renderer/gl.h`) directly on
deko3d, so every existing renderer and shader runs unchanged.
- Code: `port/renderer/dkgl/` — `dkgl.h` (API), `dkgl_internal.h`, `dkgl_core.cpp` (device,
  memory, frames, present, shader pack), `dkgl_gl.cpp` (GL state machine, objects, draws).
  Syntax-checked with host GCC/Clang -Wall -Wextra against deko3d.h; not yet compiled by devkitA64.
- Conventions match vkgl/Vulkan: device flags DepthZeroToOne | OriginUpperLeft. The installed
  deko3d is 0.5, which lacks DkDeviceFlags_YAxisPointsDown, so the pack's vertex shaders negate
  gl_Position.y (dk_pack.py passes SPIRV-Cross --flip-vert-y): the same viewport transform;
  framebuffer row 0 at NDC y=-1; default framebuffer blitted to the screen with FlipY.
- Frames: 2 slots, each with a 48 MiB ring (uniforms, dynamic buffers, uploads) and growable
  command memory; fences per slot; resources retire by frame number.
- Buffers: CPU copy; ring copy while changing, own memblock once settled.
- Textures: one memblock + image descriptor each; samplers deduped into a sampler descriptor set;
  handles via dkMakeTextureHandle; unbound units sample a 1x1 black dummy.
- Programs are PRECOMPILED: at glLinkProgram dkgl hashes FNV-1a64(vertex\0fragment\0) and loads
  `romfs:/dkgl/<key>.vert.dksh`, `.frag.dksh`, `.prog` (reflection). Missing programs fail to link
  and their sources go to `sdmc:/switch/openrac/dkgl-missing/`.
- Shader pack: `port/renderer/dkgl/pack/` (9 programs = the complete Switch set, see
  `docs/port/SWITCH_DEKO3D_SHADERS.md`). Made by `port/tools/deko3d/dk_pack.py` from a Vulkan
  `OPENRAC_DUMP_SHADERS` dump: SPIR-V -> SPIRV-Cross (GLSL 460) -> uam -> DKSH.
  (SPIRV-Cross from KhronosGroup; uam built from LostOdysseyRecomp thirdparty/uam, or devkitPro's.)
- Build wiring: CMake option `OPENRAC_SWITCH_DEKO3D` (exclusive with Vulkan) in
  `port/CMakeLists.txt`; `openrac_renderer_dkgl` in `port/cmake/Window.cmake` (defines
  `OPENRAC_DKGL` on openrac_platform); `port/cmake/Games.cmake` names the NRO
  `openrac-rac1-pal-deko3d.nro` and embeds the pack as RomFS; `platform/switch/graphics.cpp`
  opens dkgl (`Window::open_deko3d`) with no OpenGL fallback; launcher label `DEKO3D TEST`.
- Build: `claude-build-deko3d.bat` / `.sh` (build dir `port/build-switch-deko3d-game`, log
  `claude-build-deko3d.log`, output copied to `build/deko3d-test/`).
- Logs on Switch: `deko3d-startup.log`, `deko3d-runtime.log`, `dkgl-driver.log` (deko3d debug
  callback), session log `data/openrac-rac1-pal.log`. `OPENRAC_DK_COUNTERS=N` in env.txt logs
  draws/uploads/barriers per frame.

## dkgl hardware results so far (2026-10-29, 854x480, FRAME_COST + OPENRAC_DK_COUNTERS)
- Boots, plays the intro movie, menu, loads a save, plays the ship cutscene, loads Novalis and is
  playable with mostly correct scenery for ~1 minute. Status Monitor showed ~45 FPS, GPU 99%.
- Title world (~750 draws): GPU 3.2 ms/frame vs Vulkan 10-13 ms. Novalis (1200-1400 draws):
  GPU 6-7 ms, CPU submit 5-5.7 ms (Vulkan: GPU 15-22 ms). Per-draw cost is ~5 us vs ~10+ us.
- Fixed during bring-up: deko3d 0.5 has no YAxisPointsDown (Y flip moved into shaders);
  GPFIFO overflow from a DkBarrier_Full per texture upload (now barriers only when needed, and
  long lists are submitted in parts, `barrier()` in dkgl_core.cpp); dkMemBlockCreate failure from
  one memblock per texture/buffer (now `Heap` sub-allocation of 32 MiB blocks).
- The build links deko3d's DEBUG library (`OPENRAC_DKGL_DEBUG=ON`, deko3dd) so errors reach
  `dkgl-driver.log`. Turn it OFF for performance numbers.

### Open dkgl bugs (next to fix)
1. **GPU method error on Novalis after ~1 minute** (dkgl-driver.log):
   `GPU method error ... [b197:739] = 0xc1df6200`. 0xB197 = Maxwell 3D; method 0x739 =
   `VertexArray[14].Start` high word (deko3d source/maxwell/engine_3d.def): a vertex buffer
   address for attribute slot 14 is garbage. Then "the GPU queue is in an error state", then a
   Data Abort while tearing down (`TexturePool::~TexturePool` freeing a hash map: heap corruption
   or teardown after the queue error). A guard was added in `prepare_draw` (dkgl_gl.cpp): an
   attribute offset past its buffer is fed GL's constant and logged ("past its buffer") — NOT
   built or tested yet. If the log stays silent, check: deko3d 0.5's dkCmdBufBindVtxBufferState
   may leave arrays >= n enabled from an earlier draw (bind all 16 with zero-stride constants);
   and look for memory corruption (the hash-map free crash).
2. **Ship model broken** in the planet-landing cutscene (level 98, ~9 draws) — see the user's
   video 2026-10-29 01:12. Skinned models sample `palette_texture`/`light_texture` in the vertex
   stage; check vertex texture fetch, RGBA32F uploads (client GL_FLOAT), and integer attributes
   (glVertexAttribIPointer -> Sint/Uint).
3. **Ratchet not drawn correctly on the main menu** (render-to-texture menu models).
4. **White triangle shards** around the Novalis scenery (screenshot): stray vertices — same
   family as 2 (attribute formats / skinning) or index-buffer offsets.
5. **Pyrocitor gray in the vendor's side window** (seen on Vulkan too).
6. FPS still capped by CPU submit + GPU ~12-13 ms/frame with FRAME_COST on; without it the
   game showed 45 FPS. Next performance steps: release deko3d library, enable PVS culling for
   dkgl (`gl::is_vulkan()` gate in scene/level_renderer.cpp), reduce per-draw state words.

## Known gaps / next steps for dkgl
1. First devkitA64 build: fix compile errors. Then first hardware run: title screen -> Novalis.
2. Barriers are conservative (DkBarrier_Full before every texture upload/copy): tune once correct.
3. MSAA reported unavailable (GL_MAX_SAMPLES=1). glReadPixels RGBA8 only. No compute.
4. Each texture is its own memblock: pool allocations if creation is slow.
5. PVS culling is gated on `gl::is_vulkan()` in `scene/level_renderer.cpp`; enabling it for dkgl
   would cut draws further.
6. Runtime fallback compiler (uam on device, as LostOdysseyRecomp does) for programs not in the
   pack — only needed if new features add programs.
7. ChatGPT's earlier deko3d prototype (`renderer/deko3d/presenter.cpp`, `level_scene.cpp`,
   probe) is separate and untouched; dkgl does not use it.
