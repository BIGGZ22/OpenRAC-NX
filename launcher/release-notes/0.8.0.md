## The game

- **The US disc plays far more like the original.** A long list of places where the US version still did nothing, or did the wrong thing, is fixed:
  - Enemies and objects that never appeared now spawn, on Rilgar, Blarg Station, Gaspar, Orxon, Pokitaru, Gemlik Base and Quartu (where the helicopters now drop their Blarg commanders).
  - Ratchet can now walk on Batalia, Oltanis and Kalebo III, where his movement code did not run.
  - Over a hundred calls that lost a value on the way now pass what the original passes, among them Eudora's walking, Umbris's effects and grabbing ledges.
  - The Snagglebeast's shockwaves, Gaspar's turret and the Bomb Glove there, Qwark's fighter on Gemlik, Rilgar's race texts, the menus' preview models and the sky's random effects now behave as on the original.
  - Code carried over from the European version is now checked against the US code itself, which found and fixed a dozen wrong addresses and calls.
  - Measured on the same scripted runs of every planet, the US game now does what the European one does on 18 of the 19.
- **Crashes fixed.**
  - Batalia no longer crashes on either disc (on the US disc before you got control, on the European one now and then while loading).
  - Pokitaru on the US disc no longer crashes when Ratchet dives.
  - Opening most pages of the pause menu no longer crashes, and closing the pause menu on the US disc no longer does either.
  - The Suck Cannon no longer stops the game on Kerwan.
  - A texture read in another format could write one byte too many, which crashed the game at random on some planets.
- **The pause menu.**
  - Highlighting Quit Game in Options no longer blanks the menu: it used to load a picture that isn't there, writing over a large part of the game's memory (which could also empty the Gadgets and Items pages afterwards).
  - Visiting the Quick Select page no longer leaves Ratchet's wrench deformed: the page's item preview borrowed the wrench's model buffer, and the port skipped the call that puts the wrench back.
- **The Visibomb works.** Its camera no longer flies off into the sky (or crashes Hoven on the US disc): the missile flies, steers and comes back.
- **Strafe (experimental).** A new option on the Video page, off by default:
  - **Hold L2-R2**, as in Going Commando: hold either one and the camera swings behind Ratchet; then the right stick turns the camera and Ratchet with it, and the left stick side-steps. L1 still looks around and R1 still crouches.
  - **Lock with weapons**, as in Up Your Arsenal: with a weapon that fires ahead, the camera stays behind Ratchet, the right stick turns him and the left stick strafes. With anything else in hand it works like Hold L2-R2.
  - **Known limitation: no proper strafe animations yet.** The first game has no side-step or backward walk for Ratchet. Going backwards plays his walk or run in reverse; going sideways still plays his forward run, which looks odd. The plan is to bring Going Commando's or Up Your Arsenal's strafe animations over to this skeleton, taken from the player's own disc. Help is welcome, on OpenRAC's GitHub, from anyone who knows these games' animation and skeleton formats.
- **Start skips landings.** Pressing Start during a ship's landing or take-off now skips it the way Cross does, instead of fading to black while the landing went on.
- **Widescreen water.** In a picture wider than 4:3, seas, lava and sand no longer vanish at the left and right edges.
- **No leftover HUD line.** The air meter no longer leaves a one-pixel line at the edge of the screen after it hides, which showed at some window sizes.

## The launcher

- **A new look built around your games.** The launcher opens straight onto the game you last played, with every game in a list on the left and one main button in a fixed place.
- **The save editor** marks every change it is about to make and fits smaller windows.
- **Memory card backups** are listed by the note they were taken with, for example "Before editing slot 2".
- **Quieter.** The launcher no longer redraws while it sits idle.
- **Building the game** now reads your disc, so the code the decompilations don't have yet comes from your copy of the game.
- **For developers:** with Developer tools on and both discs of a game in your games folder, a switch under Play picks which one to play.

## Where the port stands

- **Every function the game runs now has working C, on both discs.** What the decompilations haven't matched yet is either backfilled C, C the build writes from the game's own instructions on your disc, or proven not to be code at all (padding, pieces of other functions, leftovers of the original linker).
- **The European game is 95.0% decompiled to matching C** (4,896 of 5,119 functions), byte for byte with the original. Today's work went back to the rac1-decomp project as well: a camera system rewritten with named fields, the calls that drop arguments the original passes in registers, 83 functional C files with their checks, three functions matched with their original assemblers, and the debug menu's real start.
- **Proven against the original:** 158 of the European game's functional C files behave exactly like the original on captured calls, up from 47 this morning, level code included.
- **Tested before this release, on both discs:** a short scripted run on every planet and 56 longer ones (every planet's main path, every weapon, the pause menu, deaths and respawns, vehicles, bosses, the title and saved games), compared frame by frame against the previous build and against each other. Both discs pass all of them.

## For contributors

- A regression harness (`port/tools/regress`, docs/port/REGRESSION.md) plays scripted routes on both discs in hidden windows, compares builds or discs frame by frame and lists every function the game reaches without working C. A prepared memory card covers saved games.
- Backfilled C is checked against the original with fcheck before it counts as done, level code included (docs/workflow/BACKFILL.md). The US disc's carried C is checked against the US code by a ctest gate (port/tools/versionmap/xcheck.py).
- hostgen writes working C from the original's instructions (the decompilation's assembly, or the player's disc) for functions with no C yet, and resolves literal addresses, offset labels, folded copies, entry points and per-level hooks the way the game's own linker and level loader do.
- docs/port/RAC1_NTSC_HINTS.md lists the US port's known trouble spots and the remaining differences between the discs.

The installers are built by the launcher workflow and are not signed. Your levels are not extracted again for this version.
