# OpenRAC

[![checks](https://github.com/OpenRAC/OpenRAC/actions/workflows/checks.yml/badge.svg)](https://github.com/OpenRAC/OpenRAC/actions/workflows/checks.yml)
[![openrac.dev](https://img.shields.io/badge/community-openrac.dev-e8a317)](https://openrac.dev/)

The PlayStation 2 Ratchet & Clank games, decompiled back into C and brought to
PC natively: Ratchet & Clank, Going Commando, Up Your Arsenal and Deadlocked.
Each game is matched function by function until it compiles to a byte-identical
copy of the original, and that C then runs on PC the way OpenGOAL brought Jak
and Daxter there. No emulation.

OpenRAC holds none of the games' data: the models, textures, sound and levels
come from your own disc.

![The OpenRAC launcher: the games, each version's progress and what is ready](launcher/docs/screenshots/library.jpg)

## Play

1. **[Download the launcher](https://github.com/OpenRAC/OpenRAC/releases/latest)**
   for your system and install it.
2. Start it and choose the folder with your PlayStation 2 disc images (`.iso`).
   It finds Ratchet & Clank there and gets it ready by itself.
3. Press **Play**.

Nothing else to install: the launcher carries the game, built for your system,
and everything that prepares it. You need the image of your own disc; OpenRAC
never downloads a game. The release page says which file to pick for your
system, and what is known not to work yet.

![A game's page: build and play, the level editor, the memory card's save slots](launcher/docs/screenshots/game.jpg)

Ratchet & Clank (PAL) is the first game on PC. The native port
([port/](port/README.md)) builds its whole decompilation into one program that
runs the game's own `main`, drawn by OpenRAC's OpenGL renderer, with its sound
effects, music and speech; what is still assembly is logged and skipped. The
design and the order of work are in [docs/port](docs/port/README.md).

## Level editor

OpenRAC includes a level editor powered by **Godot 4** ([editor/](editor/README.md)) that
turns the levels from your own disc into Godot projects:

1. **Extract**: Turn your disc's 19 levels into separate Godot projects in about 20 seconds:
   ```sh
   python3 editor/extract.py godot baserom/SCES_509.16.iso assets/levels/rac1 --split
   ```
2. **Edit**: Open any level in the Godot 4 editor (e.g. Veldin):
   ```sh
   godot --path assets/levels/rac1/level_00 -e
   ```
   Move, turn, scale, add, or delete mobys (enemies, crates, vendors, bolts, obstacles)
   and scenery (ties and shrubs) using Godot's visual scene editor.
3. **Pack & Play**: Pack your edits back into game data without altering your disc:
   ```sh
   python3 editor/extract.py pack baserom/SCES_509.16.iso assets/levels/rac1 assets/packed/rac1
   ```
   The native PC port plays your edited levels directly (`--mods assets/packed/rac1`).

The desktop launcher also includes a built-in **Mods** tab that handles extracting,
launching Godot, packing your changes, and playing your modded levels in one click.
See [editor/README.md](editor/README.md) for moby class data, pvars, and GDScript behaviour details.

## Decompiling

Contributors work from a checkout. The launcher finds it, and with **developer
tools** on in its Settings it builds the port from your tree and runs the
decompilations' builds and checks; to run the launcher itself from source:

```sh
git clone https://github.com/OpenRAC/OpenRAC.git && cd OpenRAC/launcher
corepack enable && yarn install && yarn tauri dev
```

The decompilations' own tools:

```sh
# Put images of your own discs in baserom/ (see baserom/README.md), then:
python3 tools/openrac.py discs     # identify and check them
python3 tools/openrac.py setup     # put each game's inputs where its build expects them
```

`setup` ends by printing the next command for each game. The compilers are
proprietary and not included: [toolchains/README.md](toolchains/README.md) says
what each game needs. Then follow the game's README, for example
[games/rac1](games/rac1/README.md). The launcher runs the same builds
and checks with its developer tools on.

## Repository layout

```
games/       one directory per game, one per version inside (pal, ntsc)
port/        the native PC port: runtime, hostgen, renderer, sound, the games' programs
launcher/    the desktop app: set up, build and play the games
editor/      the Godot level editor and its extractor
tools/       openrac.py (discs, setup, progress) and sources.py (imports)
docs/        policy, engine knowledge, toolchains and workflows across games
progress/    consolidated progress, generated
shared/      the function map across the games, generated
baserom/     your disc images (ignored by git)
toolchains/  compilers you supply (ignored by git)
```

[docs/LAYOUT.md](docs/LAYOUT.md) gives the rules behind it, and
[docs/README.md](docs/README.md) maps every document in the repository.

## Contributing

Read [CONTRIBUTING.md](CONTRIBUTING.md) and the
[sourcing policy](docs/policy/SOURCING.md): your own disc is the evidence, and
Sony SDK source, samples and headers, and leaked or NDA material, are never
used. Commits follow Conventional Commits (`feat(rac1/pal): ...`). AI agents
also follow [AGENTS.md](AGENTS.md). Decisions the group still has to make are
in [docs/policy/OPEN_QUESTIONS.md](docs/policy/OPEN_QUESTIONS.md).
