# The OpenRAC mod SDK

What you need to write a **native mod** for OpenRAC's native port: a small
shared library the game loads at start, which changes what the game does
through named hook points, a callback each game tick, the pad's reports and
its own settings. The design, the rules and how the port and the launcher
treat a mod are in [docs/port/MODS.md](https://github.com/OpenRAC/OpenRAC/blob/master/docs/port/MODS.md) (`docs/MODS.md` in the archive); Ratchet &
Clank's mods are in [OpenRAC/rac1-mods](https://github.com/OpenRAC/rac1-mods),
starting with the lock-strafe.

A mod of textures, models or level edits needs none of this: that is a data
pack, made with the level editor ([editor/MODDING.md](https://github.com/OpenRAC/OpenRAC/blob/master/editor/MODDING.md)).

**New to modding OpenRAC? Start with [the guides](docs/README.md)**:
[getting started](docs/getting-started.md) takes you from the template to a mod
players install by pasting your repository's link. The
[API reference](docs/README.md#reference) is generated from the headers and
type files below. This README is the SDK's own notes.

| | |
|---|---|

## A mod in brief

A mod is a folder with a manifest, `openrac-mod.json` (MODS.md, section 3:
its id, name, version, the games and discs it is for, the interface version,
its settings, dependencies and conflicts), and its library. The library
exports two functions:

```c
#include "openrac/openrac_mod.h"
#include "openrac/games/rac1.h"

OPENRAC_MOD_DEFINE("my-mod", "0.1.0")          /* openrac_mod_query: the interface and the id */

static openrac_rac1_Hero_TurnToHeading s_turn; /* what the hook goes on to */

static void turn(int32_t mode, float accel, float damping, float limit) {
    /* ... before ... */
    s_turn(mode, accel, damping, limit);        /* the game's own, or a mod's loaded earlier */
}

OPENRAC_MOD_EXPORT int openrac_mod_load(const openrac_api* api, openrac_mod* mod) {
    if (OPENRAC_RAC1_HOOK(api, mod, Hero_TurnToHeading, turn, &s_turn) != OPENRAC_HOOK_OK) {
        api->fail(mod, "no Hero_TurnToHeading hook point here");
        return 1;                                /* not loaded; the launcher shows why */
    }
    return 0;
}
```

What the table offers (MODS.md, section 6): the game's memory
(`api->memory + address`), the log, the mod's settings, hook points, a
callback after each game tick and one for each pad report, the game's
functions by name or by code address, the relocation of globals for the
level loaded, and room on the game's stack. Nothing else of the port is
reachable, and a mod links against nothing of OpenRAC's: the build refuses a
library that leaves a symbol undefined.

Several mods on one hook point chain: each calls the original it was given,
and the mod loaded last runs first. A mod for several discs keeps a table of
the addresses and names it uses on each and picks it by `api->version`
(the lock-strafe does: `lock-strafe/src/discs.h` in rac1-mods).

## In C++

`openrac/mod.hpp` is a header-only C++17 layer over the same interface,
compiled into the mod: the port sees only the two C entry points, and the C
table stays the boundary (it lasts through the port's own move to C++). The
template and rac1-mods' lock-strafe are written with it.

```cpp
#include "openrac/games/rac1.hpp"
#include "openrac/mod.hpp"

static void load(openrac::Mod& mod) {
    if (mod.game() != "rac1") throw openrac::Error("this mod is for Ratchet & Clank");  // refused, with the reason
    const auto mode = mod.setting<std::string>("mode");                                  // typed by the manifest
    mod.hook<openrac::rac1::Hero_TurnToHeading>(
        [mode](auto original, int32_t m, float accel, float damping, float limit) {
            if (mode == "slow") accel *= 0.5f;
            original(m, accel, damping, limit);   // the game's own, or a mod's loaded earlier
        });
    mod.on_frame([&mod] { auto hero = mod.memory().read<float>(0x0013F4D0); (void)hero; });
}

OPENRAC_MOD_CPP("my-mod", "0.1.0", load)   // openrac_mod_query and openrac_mod_load
```

| | |
|---|---|
| `openrac::Mod` | the table and the handle: `game()`, `version()`, `log`/`info`/`warn`/`error`, `fail`, `setting<T>(key)` (`bool`, an integer type, `float`/`double`, `std::string`) |
| `mod.hook<HookPoint>(callable)` | `callable(original, args...)`: a lambda or anything `std::function` takes; `original(args...)` goes on down the chain. Throws `openrac::Error` for a hook point this port lacks, another signature, or one taken twice. `mod.original<HookPoint>()` is the same original, to call from elsewhere in the mod |
| `mod.on_frame(fn)`, `mod.on_pad(fn)` | `fn()` after each tick; `fn(port, report, size)` on each pad report |
| `mod.function<Fn>(name)`, `required_function<Fn>`, `function_at<Fn>(address)` | game functions, typed |
| `mod.memory()` | `read<T>(a)`, `write<T>(a, v)` (any alignment), `ref<T>(a)`, `pointer(a)` |
| `mod.relocate(a)`, `relocate_level(level, a)`, `loaded_level()` | a global's address in the code loaded now |
| `openrac::StackFrame frame(mod, size)` | room on the game's stack, given back when `frame` goes |

**Exceptions stop at the boundary.** One out of `load` refuses the mod with
its message. One out of a hook is logged at error level with the mod's id and
the hook point, and the original is called, so the game goes on (a hook that
threw after calling its original has it called twice: do not throw there).
One out of a callback is logged and the callback returns. A library is one
mod, and takes a hook point once; the layer's statics are hidden, so two
mods built with it never share them.

`openrac_add_mod()` compiles C++ sources as C++17 with the compiler's own
runtime, as the port has it (libc++ on macOS, libstdc++ on Linux, the DLL
runtime `/MD` on Windows): add `CXX` to your `project()`.

## Getting the SDK

Download `openrac-mod-sdk-<version>.zip` from the
[OpenRAC releases](https://github.com/OpenRAC/OpenRAC/releases) named
`sdk-v<version>` and unpack it anywhere; no copy of OpenRAC is needed. The
version is the mod interface's `MAJOR.MINOR` and a patch for fixes to the SDK
(`VERSION`): the SDK 1.0.x builds mods for interface 1.0, which every port of
interface 1.y loads. Each release gives the archive's SHA-256, so a build can
pin it (rac1-mods' `sdk.lock` and `tools/fetch_sdk.py` do). Below, `<SDK>` is
the unpacked folder (`openrac-mod-sdk-1.0.0`), or `sdk/` in a checkout of
OpenRAC; `python3 sdk/tools/package_sdk.py` makes the archive from a checkout.

## Building

You need CMake 3.20 or newer, a C compiler (Clang, GCC or MSVC) and Python 3
for the packaging. Ninja is the quickest generator; any works.

```sh
cp -r <SDK>/template my-mod      # then set the id, the name, the target
cd my-mod
cmake -S . -B build -G Ninja -DOPENRAC_SDK=<SDK>
cmake --build build
```

(`-DOpenRACMod_DIR=<SDK>/cmake` does the same as `OPENRAC_SDK`.)

- **macOS**: Xcode's command-line tools (`xcode-select --install`) and
  `brew install cmake ninja`. A build is for the Mac's own processor;
  `-DCMAKE_OSX_ARCHITECTURES=x86_64` makes an Intel one (one architecture per
  build: join the two archives afterwards).
- **Linux**: `sudo apt install build-essential cmake ninja-build python3`
  (or your distribution's). Clang works too: `-DCMAKE_C_COMPILER=clang`.
- **Windows**: Visual Studio 2022 with "Desktop development with C++". In a
  "x64 Native Tools Command Prompt", `cmake -S . -B build -G Ninja` (or
  without `-G`, Visual Studio's own generator, and `cmake --build build
  --config Release`). Clang works through `-T ClangCL`, or with LLVM's
  `clang-cl` as `-DCMAKE_C_COMPILER=clang-cl`.

`openrac_add_mod(<target> MANIFEST openrac-mod.json SOURCES ...)` builds the
library as `<target>.dylib`, `<target>.so` or `<target>.dll` (no `lib` in
front, on any system), C11, with only the entry points visible, and lays the
mod out as its archive holds it in `build/package/<target>/`: the manifest
with its `plugin` naming this platform's library (`lib/<platform>/<file>`),
the library, and the README and LICENSE beside the manifest. The platforms are
`macos-arm64`, `macos-x86_64`, `linux-x86_64`, `linux-aarch64`,
`windows-x86_64` and `windows-arm64`.

## Packaging

```sh
python3 <SDK>/tools/package_mod.py build/package/my_mod        # dist/my-mod-0.1.0-macos-arm64.zip
python3 <SDK>/tools/package_mod.py --merge dist/my-mod-0.1.0-*.zip -o dist/my-mod-0.1.0.zip
python3 <SDK>/tools/package_mod.py --check openrac-mod.json     # the manifest only
```

The archive is checked by the rules the launcher and the port apply (MODS.md,
section 3) and is not written when the manifest breaks one. `--merge` joins
the archives each platform's build made into one for every platform, which is
what a release publishes: their manifests must be the same but for `plugin`.
The template's workflow does both on GitHub's runners (below).

The tests: `python3 -m unittest discover -s sdk/tools`.

## Script mods

A script mod is Luau files the game runs in a sandbox: no compiler, no build,
one archive for every system, Android included. Copy
[template-script/](template-script), set the manifest's id and name, write
`main.luau`, and add the folder in the launcher's Mods tab to try it. Its
manifest says `"type": "script"`, `"api": "1.1"` and `"scripts": ["main.luau"]`;
`package_mod.py <folder>` checks it and writes `<id>-<version>.zip` (the
manifest, the scripts, the .luau, .json and .md files and the license of the
folder). What a script sees of the game, the sandbox and the time each call
may take are in MODS.md, section 11; `types/rac1.d.luau` declares it for
[luau-lsp](https://github.com/JohnnyMorganz/luau-lsp). A repository of script
mods needs no release at all: the launcher installs it from its address, from
its own files, and follows its commits for updates; a tag gives it versions.

## Publishing a mod from a repository

Players install mods by pasting a repository's address in the launcher
(MODS.md, section 10), so a mod's repository keeps to its conventions, which
the template already follows:

- **The manifest** at the top of the repository (one mod), or one folder per
  mod at the top, each with its `openrac-mod.json` (several; an
  `openrac-mods.json` at the top, `{"format": 1, "mods": ["a", "b"]}`, may
  list them). Sources beside each manifest: `CMakeLists.txt`, `src/`,
  `tests/`; a data pack's files as [editor/MODDING.md](https://github.com/OpenRAC/OpenRAC/blob/master/editor/MODDING.md)
  lays them out. The top `CMakeLists.txt` builds every mod.
- **The SDK pinned**: `sdk.lock` (version, url, SHA-256) and
  `tools/fetch_sdk.py`, which downloads it into `.sdk/`. The template's lock
  has no hash yet; the first fetch takes it from the release and writes it in:
  commit it.
- **The workflow** `.github/workflows/build.yml` (the same in both templates;
  script mods are packaged without a build): build and test on Windows
  (MSVC), Linux (x86_64, aarch64) and macOS (arm64, x86_64), package, join, and
  on a tag `v<version>` (or `<id>-v<version>`) publish the release with
  `<id>-<version>-<platform>.zip`, `<id>-<version>.zip` and `SHA256SUMS`.
  The launcher downloads only an asset `SHA256SUMS` lists with the same hash.

So releasing is: set the version in the manifest, commit, push a tag
`v<version>`. [rac1-mods](https://github.com/OpenRAC/rac1-mods) uses the same
workflow, file for file.

## Installing and trying a mod

In the launcher, **Mods**, then **Add a mod**, and choose the `.zip` (or the
`build/package/<target>` folder while you work on it). Switch it on, set its
settings, and Play: the game's log (Logs, under the game's saves) says
`mods      my-mod 0.1.0` at its top, and your mod's lines after its id. A mod
that was not loaded says why on its row in the Mods tab. By hand, without the
launcher: copy the folder to `<data>/plugins/my-mod/` and list it in
`<data>/plugins/plugins.json` (MODS.md, section 5).

`<data>` is the game's set-up folder in the launcher's install folder, the
same for an installed launcher (AppImage, deb, rpm, the macOS app, the Windows
installer) and a checkout; the launcher's own folder is never written:

| System | A game's mods, by default |
|---|---|
| Linux, macOS | `~/OpenRAC/active/<game>/data/plugins/` |
| Windows | `%USERPROFILE%\OpenRAC\active\<game>\data\plugins\` |

(Settings in the launcher shows the install folder, if the player chose
another.) The launcher starts the game with `--plugins` naming that list, and
the game writes `status.json` beside it: what it did with each mod at its last
start, which is the first place to look when yours did not load. Android does
not load native mods (the system refuses code an app wrote itself).

**Purist mode** (Settings) starts the game with no mods at all; so does the
port's `--no-mods`.

## License

The SDK (everything under `sdk/`: the headers, the CMake package, the
templates, the tools and the guides) is under the MIT license
([LICENSE](LICENSE)), so a mod built with it can be under any license its
author chooses. The rest of OpenRAC, the port the mods run in included, stays
under the GPL v3 or later. The templates carry the MIT license as their
starting point; replace it with your mod's own.

## Releases

Each SDK version is a release `sdk-v<version>` of OpenRAC/OpenRAC, beside the
launcher's. SDK releases are never marked Latest (the launcher's updates read
the Latest release), and the launcher ignores releases that are not its own.
